#### 1.1.1 板卡同名引脚 PinRef 命名与网络聚合（E1）

板卡左右两列存在物理重复（同一引脚两侧均有，如 VP/VN/EN 在左列与右列都有）。需要明确命名与聚合规则，避免 PinBus 把它们当两个独立网络。

**PinRef 命名**：板卡引脚的 PinRef 形如 `board:VP`，**不带列后缀**（左列右列同名引脚 PinRef 相同）。

```ts
// PartInstance.attrs 不存列信息；catalog 的 PinDef.x/y 已含坐标
// 连线 source/target 用 PinRef = `${partId}:${pinName}`
// 例：esp:VP ——无论从板卡左侧还是右侧的 VP 引脚拖出，PinRef 都是 "esp:VP"
```

**网络聚合算法**（PinBus load 时执行）：

1. 收集所有 `connections` 的 `source` 与 `target`，解析为 `{partId, pinName}`；
2. **板卡同名引脚预聚合**：板卡定义（BoardDefinition.pins）在加载时，把左右列同名的引脚登记为同一个逻辑 PinRef（`board:VP`，无论从左侧 x=8 还是右侧 x=232 拖出）；
3. 对所有 connections 做 Union-Find：相同 PinRef 天然同网络；不同 PinRef 通过 connection 边合并；
4. 最终每个连通分量即一个 NetId，包含一组 `{partId, pinName}`，PinBus 的 `claimOutput/claimInput/read/write` 都按 PinRef 操作，底层落到 NetId。

**校验规则**：
- 同一 PinRef 重复连线 → 允许（多个元件共享板卡引脚，星型拓扑）；
- 板卡左右列同名引脚都接入 → 视为同网络（不报重复），Union-Find 自动合并；
- 板卡外的元件（如 LED）每个引脚是唯一 PinRef，不存在同名问题。

**对引擎的语义**：引擎A `MachineShim` 注册 `Pin(4, OUT)` 时，调用 `bus.claimOutput('esp:GPIO4')`；引擎B GPIO 桥转译时也用 `gpio` 数字而非 PinRef（4 即 GPIO4），PinBus 内部映射 `gpio→PinRef`。两引擎一致。

### 1.5 wokwi-resistor

| 引脚 | 角色 | 坐标 |
|---|---|---|
| 1 | passive | 4,14 |
| 2 | passive | 72,14 |

attrs：`value`(number Ω, 默认 1000)。行为：`passive-through`——P1 逻辑拓扑下视为直通（不参与压降计算），值仅展示与记录。

> **E2 电阻在 PinBus 多驱动冲突中的特殊处理**：电阻两脚 `1`/`2` 在 PinBus load 时按 `passive` 角色直接合并进同一网络（与导线等价），不形成独立驱动源——这意味着若两端各接一个输出（如 GPIO4→电阻→GPIO5，两 GPIO 都设 OUT），会被识别为多驱动冲突，触发 §03-核心模块 §4.2 规则2 的 `log.warn`。
> - 电阻不"缓冲"冲突：P1 不模拟分压，电阻 = 直通；
> - 电阻的 `value` 仅记录到 `diagram.json`，运行时不影响电平（pinBus 不读 value 字段）；
> - 若 P3 升级为 SPICE 仿真，电阻才参与压降计算（届时 PinBus 行为会调整，预留 `passive-with-value` 行为枚举）；
> - LED 串联电阻场景：`GPIO4 → R(1k) → LED.A`，LED.C → GND，电阻被短路进同一网络，LED 按 GPIO4 电平亮灭，符合实物直觉。

### 1.6 wokwi-potentiometer

| 引脚 | 角色 | 坐标 |
|---|---|---|
| GND | gnd | 12,90 |
| SIG | analog | 48,90 |
| VCC | power | 84,90 |

attrs：`value`(number 0–100%, 默认 50)。行为：`analog-source`——`produces: ["analog.value"]`；滑杆拖动→`SIG` 网络注入 `analog = value/100 * 4095`；VCC/GND 未接时不注入并提示（log.warn）。

> **E3 SIG 未接 VCC/GND 时固件读取的默认值**：
> - **未接 VCC 或 GND**：电位器不产生驱动（与 §1.6 行为一致），`analog.source` 不向 SIG 网络注入值；
> - **固件读取 SIG（`ADC.read()`）的返回值**：返回 `0`（与 ESP32 真实硬件"浮空 ADC 读 0"行为一致；不返回 NaN，避免固件 `int()` 报错）；
> - **PinBus 实现**：`bus.adcRead(pinRef)` 在 SIG 网络无 `analog` 注入值时返回 `0`，并在前端 Inspector 显示"电位器未接电源"提示；
> - **未接 SIG**（电位器 SIG 悬空）：固件 `ADC.read(SIG)` 返回 `0`，无 log（SIG 本就没接，不是错误）；
> - **GND 接但 VCC 没接**：log.warn 提示（用户大概率接错了）；
> - 这套规则保证固件不会因电路配置不全崩溃，便于教学场景的渐进式搭建。

### 1.8 wokwi-buzzer

| 引脚 | 角色 | 坐标 |
|---|---|---|
| GND（负极） | gnd | 36,66 |
| VCC（正极） | power | 36,6 |

attrs：`volume`(number 0–100, 默认 50)。行为：`sound-emitter`——电平 1 时发声（浏览器 AudioContext，音量随 attrs；`pwm.duty` 到达时按频率变调，M5 为开关音，M7 支持变调）。

> **E4 AudioContext 用户手势解锁策略**：浏览器自动播放策略要求 `AudioContext` 必须由用户手势触发 resume，否则 `state === 'suspended'` 不发声。
> - **解锁时机**：首次点击顶栏 ▶ 运行按钮时调用 `audioCtx.resume()`（一次性 resume，后续保持 running）；不依赖首次点击元件（用户可能直接 attach 工程就跑）；
> - **解锁失败处理**：若运行时 `audioCtx.state === 'suspended'`（用户绕过按钮直接 load），蜂鸣器视觉仍显示"发声"波纹动画，但不发声，Inspector 提示"点击任意位置以启用声音"；
> - **single AudioContext**：全应用一个 `AudioContext`（`apps/web/src/audio/ctx.ts` 单例），蜂鸣器与 M7 后续可能的语音/音乐元件共用，避免多实例资源占用；
> - **静音控制**：顶栏加静音切换按钮（与主题切换并列），写入 `uiStore.muted`，蜂鸣器渲染前检查 `muted` 直接 skip `OscillatorNode.start`（保持视觉但不发声）；
> - **dispose 时机**：页面 unmount/工程切换时 `audioCtx.close()` 避免悬挂的 OscillatorNode 内存泄漏；运行中 `gpio.write(0)` 时调用 `oscNode.stop()` 释放。

### 4.1 SVG viewBox 与引脚标记约定（N12）

每个元件 SVG 必须满足以下约定，使画布层能通过 DOM 查询定位引脚坐标并叠加交互热区。

**viewBox 约定**：
- viewBox 与 §1/§2 表中"封装 W×H(px)"严格一致（如 LED 为 `0 0 40 62`，板卡为 `0 0 240 380`）；
- 画布层用 `Konva.Image` 渲染时按封装尺寸 1:1 映射到画布像素；
- 引脚命中半径 6px，热区圆心坐标来自 PinDef 的 `x/y`（见 03-§2.2），与 SVG 内 `<circle>` 的 cx/cy 一致。

**引脚 `<circle>` 命名约定**：
- 每个引脚在 SVG 内以 `<circle id="pin-{pinName}" cx="{x}" cy="{y}" r="3" />` 标记，`pinName` 与 §1/§2 引脚表 `name` 列严格一致（板卡形如 `pin-GPIO4`，元件形如 `pin-A`）；
- 引脚圆默认以 `var(--pin-stroke)` 描边、透明填充，hover/选中时由画布层叠加外环高亮（SVG 内不绘制高亮态）；
- 板卡左右列同名引脚（如 GPIO4 在左右列均存在）**只在 SVG 内绘制一次** `<circle>`（按 §1.1.1 E1 的 PinRef 不带列后缀规则），坐标取左列 x 值；右列的同名引脚由画布层在 board catalog PinDef 中独立登记（右列 x=232 的同名条目），SVG 不再画第二个 circle。

**示例（wokwi-led.svg）**：

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 40 62" width="40" height="62">
  <!-- 主体 -->
  <rect x="10" y="20" width="20" height="30" rx="4" fill="var(--panel)" stroke="var(--panel-border)"/>
  <circle cx="20" cy="14" r="6" fill="var(--led-off, #333)" />
  <!-- 引脚：name 与 §1.2 表一致 -->
  <circle id="pin-A" cx="20" cy="6"  r="3" stroke="var(--pin-stroke)" fill="transparent"/>
  <circle id="pin-C" cx="20" cy="56" r="3" stroke="var(--pin-stroke)" fill="transparent"/>
</svg>
```

**板卡示例片段（board-esp32-devkit-c-v4.svg）**：

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 240 380" width="240" height="380">
  <rect x="4" y="4" width="232" height="372" rx="8" fill="var(--panel)" stroke="var(--panel-border)"/>
  <!-- 板卡左列 GPIO4（右列同名引脚不重复绘制） -->
  <circle id="pin-GPIO4" cx="8" cy="160" r="3" stroke="var(--pin-stroke)" fill="transparent"/>
  <!-- ... 其他引脚圆按 §1.1 表坐标逐个绘制，同名引脚仅画左列 -->
</svg>
```

**热区叠加**：画布层渲染元件时，遍历 `document.getElementById('pin-...')` 取 `cx/cy` 属性，在 Konva 层叠加一个 r=6 的透明 Circle 作为 pointer 命中热区；pointer events 不依赖 SVG 内 `<circle>` 的命中（SVG 仅作可视化与坐标源）。

**主题 token 对应**：`--panel`、`--panel-border`、`--pin-stroke`、`--led-off` 在 04-§3 主题 token 表中登记；运行态发光（如 LED 点亮）由画布层在 SVG 之上叠加额外 Konva 节点实现，SVG 本身保持静态。

## 5. 连线校验规则（画布 + diagram.json 导入时）

| 规则 | 级别 | 提示方式 |
|---|---|---|
| 输出对输出直连（两驱动） | 警告 | 引脚红点 + log.warn（允许，运行时冲突检测兜底） |
| 接到 Flash 专用脚（GPIO9/10/11） | 警告 | 引脚黄点 |
| 元件电源脚未接（VCC/GND 悬空） | 提示 | Inspector 面板清单 + 运行前检查弹窗（可忽略继续） |
| I2C SDA/SCL 未上拉 | 提示 | 同上（虚拟总线不强制上拉） |
| 同一引脚重复连线 | 允许 | 多元件可共享同一网络（星型），不算错误 |
| 超过规模上限（《06-边界说明》§3） | 阻止 | 保存/导入时拒绝 |
