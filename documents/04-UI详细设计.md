## 4. Library 元件库面板

| 区块 | 控件 | 规格 |
|---|---|---|
| 搜索框 | Input + 清除 | 200ms 防抖，按名称/类型过滤 |
| 分类树 | Accordion | 分类：开发板 / 基础IO / 传感器 / 显示 / 电源，含计数徽标 |
| 元件卡片 | 96×72 | SVG 缩略图 + 名称；hover 提升 + 描述 tooltip |
| 拖拽 | 自研 pointer 事件 | 拖入画布落点为卡片中心；拖回面板取消 |

> **D1 实现说明（react-konva 与 HTML5 DnD 不兼容）**：react-konva 的 Stage/Node 跑在 Canvas 内，HTML5 原生 `dragstart/dragover/drop` 事件不会在 Canvas 内部元素上触发（浏览器把 Canvas 当作单一原子元素）。改用统一指针事件模拟：
> - 元件卡片：`onPointerDown` 记录起点 + 卡片 type → `onPointerMove` 超过 4px 阈值进入 dragging 态 → 显示半透明跟随光标（用 `position: fixed` 的 DOM 元素，不走 Konva）→ `onPointerUp` 时若光标落在 Stage 内（用 `Stage.getClientRect()` 命中检测），转换为画布坐标 → `circuitStore.addPart(type, snapToGrid(pt))`；
> - 不用 HTML5 DnD 的 `dataTransfer`，避免 iframe/跨窗口限制；
> - 触屏：同一指针事件路径天然支持（PointerEvent 统一鼠标/触摸/笔）。

元件卡片数据源：`GET /api/parts`（categories 来自《05-元件清单》）。

## 6. 画布（Canvas）交互状态机

### 6.1 指针状态机

```
        ┌─────────┐ hoverPin                 dragWire
        │  idle   ├────────────► [pinHover] ───────────────► [wiring]
        └────┬────┘  (可从任意态进入)  ▲ mouseup on pin   │ Esc/落空=取消
             │ space+drag / 中键      │                  ▼ 成功
             ▼                        │              [idle] + 新增连线
         [panning] ◄──────────────────┘
        ┌─────────┐ dragPart
        │  idle   ├──────────► [moving] ── mouseup ──► [idle]（吸附/标脏）
        └────┬────┘
             │ marquee（左键空白处拖拽）
             ▼
         [marquee] ── mouseup ──► [idle]（多选）
```

### 6.2 视图变换
- 滚轮：以指针为中心缩放（0.25–4x，步进 10%）；
- Space+左键 / 中键：平移；
- `Ctrl+0`：复位 100%；`Ctrl+1`：适应窗口。

### 6.3 连线（wiring）细部
1. 进入 [pinHover]：引脚放大 1.5×+光标 crosshair；
2. [wiring] 中：预览折线（起: 固定锚，终: 指针实时正交化——先垂直后水平）；
3. 命中目标引脚吸附（6px 阈值），松开生成 Connection（颜色自动轮转 8 色）；
4. Esc 取消；点击空白处取消；落回源引脚取消。

### 6.4 运行态视觉
- 引脚电平点：高电平=主题 accent 色+外发光，低电平=灰；
- LED 元件按 duty 混色（alpha 叠加）；OLED 直接绘制 framebuffer；
- 运行中元件拖拽仍允许（电路变更即时生效，引擎热更新：引擎A 支持；引擎B 提示"运行中电路修改将在复位后生效"）。

## 7. BottomPanel 四个 Tab

### 7.1 代码编辑器
- Monaco 单实例多 Tab：`main.py`（引擎A）/ `sketch.ino`（引擎B）/ `lib/*`；
- Tab 右键：重命名/删除/新建文件；
- 底部状态栏：光标位置、语言、编码；`Ctrl+S` 保存文件；
- 引擎B编译错误：/problems 面板列出 `file:line:col + message`，点击跳转。

> **C3 Monaco Worker 在 Vite 下的配置**：Monaco 在浏览器内依赖 4 个 web worker（editor.worker/ts.worker/json.worker/html.worker），用 `?worker` 后缀导入；不配置会导致 worker 加载 404、编辑器卡顿。
>
> ```ts
> // apps/web/src/monaco/setup.ts（在入口 main.tsx 调用 setupMonaco()）
> import * as monaco from 'monaco-editor';
> import editorWorker from 'monaco-editor/esm/vs/editor/editor.worker?worker';
> import jsonWorker from 'monaco-editor/esm/vs/language/json/json.worker?worker';
> import tsWorker from 'monaco-editor/esm/vs/language/typescript/ts.worker?worker';
>
> self.MonacoEnvironment = {
>   getWorker(workerId: string, label: string) {
>     if (label === 'json') return new jsonWorker();
>     if (label === 'typescript' || label === 'javascript') return new tsWorker();
>     return new editorWorker();   // 默认（python/cpp 走 basic-LR）
>   },
> };
> export function setupMonaco() { /* 触发 side-effect import，确保 worker URL 注入 */ monaco; }
> ```
>
> `vite.config.ts` 不需要额外 worker 配置（`?worker` 是 Vite 内置语法）；Monaco 的 `editor.all.ts` 体积大（~5MB），生产构建走 `manualChunks` 把 monaco 单独切 chunk，按 Tab 语言懒加载（dynamic import `monaco-editor/esm/vs/editor/editor.api`）。
>
> Python/C++ 高亮：不引入 language server（体积大），用 Monaco 的 Monarch 语法（自带的 `python.ts`/`cpp.ts` token pattern），足以高亮与括号匹配。

### 7.2 diagram.json
- Monaco JSON 语言；右上按钮：格式化 / 应用到画布 / 放弃；
- 应用时经 `CircuitValidation`，失败显示行内错误且不生效。

### 7.3 串口监视器
```
┌ 工具栏 ────────────────────────────────────────────────┐
│ [连接状态●] 波特率[9600/115200▾] 自动滚动[✓] 清屏 │ 发送[______][▶发送] │

### 7.4 逻辑分析仪（M11）

## 8. 工程列表页（`/`）

- 卡片：名称、板卡徽标、引擎徽标、更新时间、最近缩略图（画布截图，M3 后提供）；
- 操作：打开 / 复制 / 导出 / 删除（二次确认，输入工程名确认）/ 导入（拖拽 JSON 到页面任意处）；
- 右上：新建（空白 / 从示例选择：下拉列出 examples 表）。

> **D3 电路缩略图实现**：用 Konva 自带的 `stage.toCanvas({ pixelRatio: 0.5 })` 导出 PNG dataURL，存到 `projects.thumbnail` 字段（SQLite TEXT，base64，约 4–10KB/张）。
> - 触发时机：用户保存工程（PUT）前在内存画布上截图（不阻塞保存流程，异步生成）；
> - 不引入 html2canvas：Konva 原生 API 更快且无 DOM-to-canvas 跨域限制；
> - 列表页 `<img src={thumbnail}>` 直接渲染，dataURL 不走 REST 请求（避免工程列表 N+1 查询）；
> - 缩略图大小：固定 240×160，按比例缩放画布（不展示 Overlay 电平高亮），PNG 压缩；
> - 工程未打开过画布（仅新建未编辑）：返回默认占位 SVG（板卡图标 + "空工程"）。

## 10. 快捷键表

| 快捷键 | 动作 |
|---|---|
| `Ctrl+S` | 保存当前文件/工程 |
| `Ctrl+0` / `Ctrl+1` | 缩放复位 / 适应窗口 |
| `Space`+拖拽 | 平移画布 |
| `Del` / `Backspace` | 删除选中（元件含级联确认） |
| `Ctrl+C/V` | 复制/粘贴元件（id 重生成） |
| `Ctrl+Z / Ctrl+Shift+Z` | 撤销/重做（circuitStore 历史栈，深度 50） |
| `R` | 旋转选中元件 90° |
| `Esc` | 取消当前操作（wiring/框选/弹层） |
| `F5`（编辑区外） | 运行/停止切换 |

> **D2 撤销/重做实现**：用 [zundo](https://github.com/charkour/zundo)（zustand 官方推荐的 temporal middleware），不手写。
> - `circuitStore` 包 `temporal` 中间件：`import { temporal } from 'zundo'`；`const useCircuitStore = create<CircuitStore>()(temporal(persist(...)))`；
> - 自动追踪 `parts`/`connections` 数组与 `attrs` 变化（用 `partialize` 排除 `dirty`/`selectedPartId` 等瞬态字段，避免无意义的 history 条目）；
> - 历史栈深度 50（与 §10 表一致），超出自动丢弃最旧；
> - 撤销/重做经 `useCircuitStore.temporal.getState().undo()/redo()` 触发，自动重渲染画布；
> - `replaceDoc`（打开工程/JSON 视图导入）走 `clear()` 清空历史栈（避免跨工程撤销到上一个工程）；
> - 工程保存（PUT 成功后 `dirty=false`）不进历史栈（partialize 排除）。

### 11.1 Monaco 主题与全局主题同步

Monaco 自带 `vs-dark` 与 `vs`（亮）两套主题，需与 §11 全局 `--theme` 同步切换：

```ts
// apps/web/src/monaco/theme.ts
import { editor } from 'monaco-editor';
import { useUiStore } from '@/stores/ui';

const monacoTheme = { dark: 'vs-dark', light: 'vs' } as const;

export function syncMonacoTheme() {
  const theme = useUiStore.getState().theme;
  editor.setTheme(monacoTheme[theme]);   // 全局生效，所有 editor 实例
}

// 在 ThemeProvider 切换时调用
useUiStore.subscribe((s, prev) => s.theme !== prev.theme && syncMonacoTheme());
```

- 不自定义 Monaco 主题：`vs-dark` 与 §11 暗色 token 足够协调；自定义 token 太琐碎（编辑器语法高亮色与 UI 色板不共用）；
- 引擎A/B 错误面板的 traceback 用 Monaco readonly editor 渲染，同样随主题切换；
- `state` 灰/`error` 红等徽标色与 §11 token 对齐（用 CSS 类，不走 Monaco）。

### 11.2 i18n 策略

**一期定位**：中文为默认语言，英文为可切换语言；不引入完整 i18n 框架（单机定位、文案量不大）。

- **文案源**：`apps/web/src/i18n/zh-CN.ts` + `en-US.ts`，键值对象（`{ 'app.run': '运行' }`），`useTranslation(key)` 直接 `return dict[key] ?? key`；
- **切换**：`uiStore.locale: 'zh-CN'|'en-US'`，订阅后整页 React 树重渲染（不持久到 IndexedDB 也行，每次启动读 settings 表）；
- **不引入 react-i18next**：50 个文案点用纯字典足够，避免 80KB 依赖；P3 若文案爆炸再评估；
- **不翻译的项**：固件代码（main.py/sketch.ino）、PinRef（`esp:GPIO4`）、REST 路径、错误码枚举（`PROJECT_NOT_FOUND`）、JSON 字段名；
- **后端 i18n**：错误响应 `error.code` 为枚举不变，`error.message` 一期固定英文（前端按 code 映射到本地化提示），避免后端也维护双语。

## 12. 空状态与引导

| 位置 | 空态内容 |
|---|---|
| 画布（无元件） | 居中引导卡："从左侧元件库拖入元件开始搭建"+ 按钮载入 blink 示例 |
| 串口（未运行） | "点击顶栏 ▶ 运行以查看串口输出" |
| 逻辑分析仪（未捕获） | "添加通道并开始捕获" |
| 工程列表（无工程） | "新建第一个工程 / 导入 JSON" |

首次进入工作台：一次性引导浮层（3 步：拖元件→连线→运行），`settings.firstTourDone` 记忆。

> **D4 首次引导浮层实现**：用 [react-joyride](https://github.com/gilbarbara/react-joyride)（成熟、可控的 tour 库，约 30KB）。
> - 3 步 beacon + tooltip：① 元件库面板（高亮 Library 区，"从这里拖入 ESP32 板卡"）→ ② 画布引脚（高亮某 PinRef，"从引脚拖出连线到 LED 阳极"）→ ③ 顶栏运行按钮（高亮 ▶，"点击运行查看仿真"）；
> - target 用 CSS 选择器（`[data-tour="library-panel"]` 等），元件/按钮上加 `data-tour` 属性而非依赖 className（避免样式重构破坏定位）；
> - `continuous: true`（连续模式），`showSkipButton: true`，`disableOverlayClose: true`（防误关）；
> - 完成或跳过写 `settings.firstTourDone=true`，不再弹；
> - 不用 driver.js/shepherd：前者维护停滞，后者依赖 popper.js 体积大；react-joyride 与 React 18 兼容。

> 元件库与画布上的空态引导卡（"从左侧元件库拖入元件…"）是常驻的，与一次性 tour 互不冲突——tour 完成后空态仍显示直到元件被拖入。
