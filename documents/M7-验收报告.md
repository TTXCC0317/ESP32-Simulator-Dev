## 5. 缺陷与修复（M7 新增）

| # | 级别 | 描述 | 修复 | 跟踪 |
|---|---|---|---|---|
| 1 | S2 | **findings F2 订正**：findings 原记 "analogWrite/analogRead 在 core 3.x 是 weak alias" 有误。实测 core 3.3.10 `esp32-hal-ledc.c` 中 `analogWrite`/`analogWriteFrequency` 是强定义（非 weak alias），不暴露 `__analogWrite`/`__analogWriteFrequency` 强符号供转调 | glue 用 ESP-IDF ledc API 直接驱动外设；BuildService 编译命令注入 `-Wl,--allow-multiple-definition` 解决同名强定义冲突 | 03-§7.2.2 glue 侧 PWM/ADC 覆盖段 |
| 2 | S1 | **QEMU Espressif fork 不模拟 ADC 外设**：servo-pot ×B 100% Cache error panic。转调 `__analogRead` 进入 `adc_oneshot_ll_get_event` 等待不存在的 ADC 完成事件 → "Cache disabled but cached memory region accessed" panic。addr2line 回溯定位到 `adc_oneshot_ll_get_event → __analogRead → analogRead → loop` | glue `analogRead` 短路：有注入返回注入值，无注入返回 0（与 05-§1.6 E3 一致），永不转调 `__analogRead`；extern 声明移除 | 03-§7.2.2 + 06-§3 "QEMU 不模拟 ADC" 条目 |
| 3 | S1 | **enforceQuota 误删刚编译产物**：Golden CLI 内存库 + data/builds/ 累积 ~2GB 历史孤儿目录 → `dirSize(root)` total 虚高 → DB 里只有刚 submit 的一行被当作"最旧"删除 → `ENOENT flash.img` | `enforceQuota` 改为只统计 DB 里有的 buildId 目录大小；新增 `cleanupOrphanedBuildDirs()` 函数，Golden CLI 启动时调用清理孤儿目录；补 2 测试覆盖（孤儿不参与配额 + 清理逻辑） | 03-§7.1 磁盘配额段 |
| 4 | S3 | **arduino-cli AppData 写入被沙箱拒绝**：Trae 沙箱拒绝 `%LOCALAPPDATA%\arduino\sketches` 写入 | BuildService 沙箱三保险：①cli.yaml 全限定 directories 到 data/；②compile 前插 `--config-file` + `--build-path`；③env 同步 `ARDUINO_DIRECTORIES_*` | 03-§7.1 沙箱三保险段 |
| 5 | S3 | **QEMU 双核缓存仿真 flake**（P1 遗留缺陷 2，未变） | 已缓解：golden 引擎B panic 检出换会话重试一次；根治依赖上游 QEMU fork 更新 | 06-§3 QEMU 行 |

**结论**：4/6 核心场景 PASS（双引擎程序运行 + 串口输出 + 元件渲染均正常）；2/6 画布交互场景需用户人工验证（电位器拖动 + 警告红框）。
